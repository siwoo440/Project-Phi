# 임시 에셋 규격과 교체 계획

기준일: 2026-11-07. 이 문서의 크기·프레임 수·입력 설정은 제작과 교체를 시험하기 위한 **임시 제안**이며 최종 아트 디렉션이나 확정 사양이 아닙니다. 실제 에셋을 교체한 후 화면 가독성과 조작감을 확인해 조정합니다.

---
## 기획서에서 확인한 내용

[기획서 1.4](https://docs.google.com/document/d/1Y8ZQw0Hr8II-M7drDmApz_opwwH_2sNFR54sO2Z4cPU/edit)는 2D 탑뷰와 가독성을 기준으로 하고, 픽셀아트와 2D 일러스트 중 최종 스타일을 정하지 않았습니다. 1.10은 캐릭터 8방향 스프라이트 또는 회전 무기 표현을 후보로 제시합니다. 관련 본문에서 스프라이트·타일·아이콘 크기, Pixels Per Unit(PPU), 애니메이션 프레임 수의 확정 수치는 확인하지 못했습니다.

프로젝트는 Unity 6000.3.21f1의 URP 2D를 사용합니다. 이전 전달문의 게임 화면 참고 이미지는 확인하지 못했습니다. 기획서의 검·활·지팡이·슬라임 점액 원본 이미지는 아래 용도로 연결했습니다.

---
## 현재 시험 화면

전투 코드의 `PrototypeBootstrap`은 런타임에 흰색 1픽셀 텍스처로 정사각형 스프라이트를 만들고 색상·크기로 플레이어와 슬라임을 구분합니다. 플레이어의 도형 크기는 약 0.7×0.7 월드 단위, 슬라임은 기본 0.65×0.65이며 슬라임의 예고에는 도형 크기 변화를 사용합니다. 조준은 별도의 막대로 표시합니다. 플레이어·적 본체의 텍스처 교체용 인스펙터 연결과 스프라이트 애니메이션은 아직 구현되지 않았습니다.

## 기획서 이미지 적용 현황

| 그림 | 기획서 위치 | 현재 게임 적용 |
|---|---|---|
| 검 | 1.12.12 근접 무기 | `Equip Sword` 버튼 아이콘 |
| 활 | 1.12.13 원거리 무기 | `Equip Bow` 버튼 아이콘 |
| 지팡이 | 1.12.14 마법 무기 | `Equip Staff` 버튼 아이콘 |
| 슬라임 점액 | 1.15.6 재료 2 | 슬라임 사망 시 시험 전리품 |

원본 PNG는 `Assets/Phi/Resources/PhiArt`에 보관합니다. 네 이미지는 각각 1254×1254이고 투명 채널을 포함합니다. 스프라이트 가져오기에서 PPU 1254와 Bilinear 필터를 사용하며, 전리품은 기존 0.3월드 단위 도형 크기를 유지합니다. 무기 아이콘은 버튼의 클릭 판정에 참여하지 않습니다. 이미지가 없으면 기존 도형·글자 표시를 유지합니다. 실제 화면에서 크기와 가독성은 미검증입니다. 기획서의 다른 장비·아이템 그림은 해당 기능이 구현될 때 적용합니다.

## 픽셀아트 시험용 제안

아래 제안은 픽셀아트를 시험할 경우의 기준입니다. 일러스트 스타일을 선택하면 필터링과 해상도를 다시 결정합니다.

| 항목 | 임시 제안 | 이유 |
|---|---|---|
| 이미지 형식 | 투명 배경 PNG | 캐릭터와 배경의 분리 |
| PPU | 64픽셀 = 1월드 단위 | 64픽셀 캔버스 한 장을 기본 1월드 단위로 환산 |
| 플레이어·일반 적 캔버스 | 프레임당 64×64픽셀 | 크기와 피벗을 통일한 교체 시험 |
| 기본 타일 | 64×64픽셀 | 1×1월드 단위 격자 시험 |
| UI 아이콘 | 32×32픽셀 원본 | 작은 UI 아이콘 제작 시험. UI는 월드 PPU와 별개 |
| 피벗 | 시험 캐릭터 중앙 `(0.5, 0.5)` | 현재 플레이어와 슬라임의 위치 기준 유지 |
| 픽셀 필터·압축 | Point, 압축 없음으로 시험 | 픽셀 경계의 흐림과 압축 영향 확인 |

64×64픽셀 전체가 차 있다고 가정하면 64 PPU에서 기본 크기는 1×1월드 단위입니다. 현재처럼 본체에 0.7 또는 0.65 배율을 적용하면 각각 0.7 또는 0.65월드 단위가 됩니다. 실제 그림의 투명 여백과 보스 크기는 별도 시각 검증 후 조정합니다. 이 배율은 공격 사거리나 피해 판정의 크기를 바꾸는 근거로 사용하지 않습니다.

## 방향과 최소 애니메이션 제안

- 플레이어 몸체: 8방향을 시험 기준으로 두되, 정지·이동 방향 표현과 마우스 조준은 분리합니다. 무기나 조준 표시의 회전은 커서 방향을 따릅니다. 8방향이 최종 결정된 것은 아닙니다.
- 슬라임: 형태가 대칭인 시험 그림은 우선 1방향을 사용합니다. 몸을 부풀리는 예고가 식별돼야 합니다.
- 플레이어 최소 목록: 대기, 이동, 검 공격, 피격, 사망.
- 슬라임 최소 목록: 대기 또는 접근, 공격 예고, 돌진, 피격, 사망.
- 프레임 수·재생 속도는 미확정입니다. 검 공격 간격 0.55초와 슬라임 예고·돌진 시점은 전투 데이터 및 판정이 기준이며, 애니메이션은 이를 따라 표시합니다.

## 교체 절차와 검증 기준

1. 실제 그림을 준비하면 프레임 캔버스·투명 여백·피벗·PPU와 `.meta` 파일을 함께 관리하고, Unity의 Sprite Import 설정을 위 시험 기준에 맞춥니다.
2. 현 코드의 `Shape`는 `Texture2D.whiteTexture`를 직접 사용하므로 파일을 넣는 것만으로는 교체되지 않습니다. 먼저 플레이어와 슬라임의 표시용 스프라이트를 설정 가능한 참조로 연결하고, 미지정 시 임시 도형을 유지하는 구조를 구현해야 합니다.
3. 본체 그림과 체력 막대의 스프라이트를 분리합니다. 현재 체력 막대가 본체 스프라이트를 공유하므로 캐릭터 그림으로 막대가 바뀌지 않도록 확인합니다. 슬라임 예고의 크기 변화는 표시용 자식에 적용하는 방식을 검토합니다.
4. 같은 씬에서 임시 도형과 시험 스프라이트를 각각 사용해 위치·크기·정렬·피격 표시·조준과 부채꼴 판정이 유지되는지 확인합니다. 재시작 후에도 선택된 에셋이 유지되는지 검증합니다.
5. 방향·애니메이션을 추가할 때 이동 중 조준, 공격 시점, 사망과 재시작을 재검증합니다. 플레이어·적 본체의 이미지 교체와 수동 화면 검증은 아직 수행하지 않았습니다.
