# 설계 결정

이 문서는 첫 구현에 채택한 기준과 확인이 필요한 기획 사항을 구분합니다. Google 기획서의 전체 탭 계층과 관련 본문 1.4, 1.5, 1.9~1.13, 1.12.12, 1.14, 6.2, 6.4를 확인했습니다. 나머지 본문의 확인 여부는 별도로 관리합니다.

---
## 첫 구현 기준

- 장르는 2D 탑뷰이며 초기 플랫폼은 Windows PC, 실행 방식은 싱글 플레이와 로컬 저장입니다.
- WASD로 이동하고 대각선 이동속도를 정규화합니다. 마우스 조준은 이동 방향과 독립적입니다.
- 좌클릭은 일반 공격이며 홀드 시 공격 간격에 따라 반복합니다. UI 클릭은 전투 공격으로 전달하지 않습니다.
- Q/E/R은 서로 다른 공용 스킬을 장착하는 슬롯입니다. 회피는 Shift, 상호작용·수집은 F입니다. 이 조작의 후속 구현 여부는 진행 현황에서 관리합니다.
- 던전 진행은 시간별 강제 몬스터 교체가 아니라 구역 진입·목표 달성·오브젝트 상호작용 등 조건을 기준으로 합니다.
- 캐릭터·무기·적 등의 설정과 실행 상태를 분리하고 공통 피해 계산을 한 경로에서 처리합니다.
- 슬라임의 기획상 행동은 느린 접근 후 몸을 부풀려 예고하고 짧게 돌진하는 것입니다.

일반 공격은 마나를 소비하지 않고 한 공격에서 같은 적에게 의도하지 않은 중복 피해를 주지 않습니다. 시험 시작 무기는 `PrototypeSettings` 에셋의 `startingWeapon`에서 검·활·지팡이를 선택합니다. 기본값은 검입니다. 첫 전투의 공격은 피해 검증을 위해 비치명타로 고정하며 치명타 확률은 후속 작업입니다.

시험 공간에서는 화면 하단의 세 버튼으로 전투 중 무기를 교체합니다. 이 조작과 전투 중 교체 허용은 임시 정책이며 영구 소유·인벤토리 규칙을 확정하지 않습니다. 선택 상태는 에셋과 분리합니다. 교체해도 기존 공격 대기 시각과 비행 중 투사체의 발사 정보가 유지됩니다. UI에서 시작한 클릭·드래그는 공격을 차단하고 사망 중 선택을 막습니다. 재시작하면 에셋의 시작 무기로 돌아갑니다. 투사체와 폭발 효과는 현재 생성·해제하며 풀링은 미구현이고 생성·해제 비용은 측정하지 않았습니다.

공용 스킬 후보 12종의 이름과 판정 유형을 목록으로 제공하고 `PrototypeSettings`에서 전투 시작 전 Q/E/R을 선택합니다. 마을과 준비 화면은 아직 없어 실행 중 스킬 변경은 제공하지 않습니다. 화염탄·회오리 베기·치유의 빛은 확정 조합이 아닌 임시 추천 시험값이며, 모든 후보의 시험 선택은 실제 획득이나 해금을 의미하지 않습니다. 세 슬롯은 무기와 독립적인 실행 상태로 복사됩니다. 시험 중 빈 값·목록에 없는 값·중복은 해당 슬롯을 비활성화하고 오류를 표시하며 기존 전투는 유지합니다. 일반적인 빈 슬롯 정책은 미정입니다. 화염탄·회오리 베기·치유의 빛을 구현했으며 나머지 9종은 미구현으로 표시하고 자원을 소비하지 않습니다. 상태 안내는 영문이며 표시 영역에서 시작한 클릭은 전투 공격을 차단합니다. 실제 화면 가독성은 검증하지 않았습니다.

기본 최대 마나는 50, 자연 회복은 초당 3이며 마나와 슬롯별 쿨다운은 전투마다 독립적으로 관리합니다. 화염탄은 공격력의 140%·마나 10·쿨다운 5초, 회오리 베기는 130%·마나 14·쿨다운 9초, 치유의 빛은 최대 체력의 15%·마나 18·쿨다운 20초입니다. 공격력은 시전 당시 기본 공격력과 장착 무기 공격력을 한 번 합산하며, 검 기본값과 방어력 2인 슬라임 기준 피해는 화염탄 29·회오리 베기 27입니다. 사망 중 스킬 입력과 마나 회복·쿨다운 진행을 중단하고 재시작 시 상태를 초기화합니다.

화염탄의 사거리 7·초당 속도 14·충돌 반경 0.05, 회오리 반경 2와 대상 수 무제한, 벽 가림은 임시 정책입니다. 사거리·속도·회오리 반경은 `PrototypeSettings`에서 조정하며 화염탄 충돌 반경은 코드 상수입니다. 화염탄은 발사 방향과 공격력을 고정하고 첫 생존 적에 적중하며 벽·맵 경계에서 소멸합니다. 회오리는 중심이 반경 이내이고 비트리거 장애물 뒤에 있지 않은 생존 적을 한 번씩 타격합니다. 치유량은 최대 체력의 15%를 버림하며 만피나 회복량 0일 때 자원을 소비하지 않습니다. 같은 프레임의 키 입력은 Q→E→R 순서로 처리하고, 텍스트 편집 포커스 중에는 차단합니다. 시전 선후딜과 취소 구간은 임시로 두지 않습니다. 실제 화면·조작감과 밀집 전투 성능은 미검증입니다.

회피는 양쪽 Shift의 누름 시 시작하며 이동 키 방향을 우선하고 입력이 없으면 현재 조준 반대 방향을 고정합니다. 기본 최대 스태미나 100, 비용 25, 이동 시간 0.25초, 대기시간 1.2초, 회복 대기 1초 및 초당 재생 15는 기획의 시험 기준입니다. 회피 거리 2월드 단위와 시작부터 0.25초 무적은 임시값이며 `PrototypeSettings`에서 조정합니다. 회복 대기는 이동 종료 후부터 계산하고 프레임 내 대기가 끝난 이후의 시간만 회복에 사용합니다.

새 회피는 Shift 입력 프레임에 비용·쿨다운·무적을 적용하고, 입력 이전에 경과한 프레임 시간으로 새 타이머가 줄지 않도록 이동은 다음 프레임에 시작합니다. 발동 프레임과 이동 중 새 공격·스킬을 차단하되 이미 발사한 투사체와 기존 쿨다운은 유지합니다. 이동 중 짧게 눌렀다 놓은 공격은 버리고, 종료 후에도 누르고 있는 공격은 기존 간격에 따라 재개합니다. 텍스트 편집 중 회피는 막고 일반 버튼 선택은 허용합니다.

회피 경로는 씬 외곽 경계와 플레이어 크기 0.7×0.7의 BoxCast로 `PhiObstacle` 비트리거 장애물을 검사합니다. 시작점의 OverlapBox는 접촉 여유까지 후보로 반환하므로 임시 플레이어 크기 트리거의 `Collider2D.Distance`를 검사하고 모서리 반경이 0인 박스·원형 장애물의 접촉 여유를 보정합니다. 전역 `Physics2D.defaultContactOffset` 0.01과 0.02 조건에서 이 두 형태의 거리 보정을 시험했습니다. 보정된 간격과 접촉 법선의 지지선을 기준으로 접근 거리를 제한하기 때문에 원형 장애물에 비스듬히 이동할 때 실제 접촉 전 보수적으로 멈출 수 있습니다. 이외의 Collider 유형과 모서리 반경이 있는 박스는 침투 여부가 불명확하면 보수적으로 차단하며 접촉 지점에서 반대 방향으로 회피하지 못할 수 있습니다. 내부에서 시작하면 차단하고 벽에 닿으면 남은 회피 시간 동안 정지합니다. 검사 도형은 검사 시에만 활성화하며 전투 종료 시 제거하고, 씬 맵과 설정 에셋은 수정하지 않습니다. 일반 이동의 내부 장애물 충돌은 여전히 미구현이며 실제 화면·조작·성능 확인이 남았습니다.

19일차 시험에서는 슬라임 사망 전이마다 슬라임 점액 1개를 고정 생성합니다. 이는 실제 드롭 확률·수량을 확정한 것이 아닙니다. 화면의 수집 횟수는 전투 중 임시 카운트이며 재시작 시 초기화됩니다. 정식 인벤토리·아이템 스택·저장·귀환 보상은 미구현입니다. 드롭은 동적 전투 오브젝트이고 씬에 저장된 맵 바닥과 경계는 변경하지 않습니다.

F 누름 시작마다 1회, 반경 1.5월드 단위 안의 가장 가까운 활성 대상을 선택해 작동합니다. 대상은 월드 표식과 영문 안내로 표시하며 거리가 같으면 활성 등록 순서를 따릅니다. 위 반경·동률 순서·비트리거 `PhiObstacle` 벽 가림은 임시 시험 정책이며 반경은 `PrototypeSettings`에서 조정합니다. 사망·회피 중이나 텍스트 편집 포커스 중에는 수집을 막습니다. 대상 자신의 자식 Collider는 벽 가림에서 제외합니다. 사망 전이와 수집 확정은 각 인스턴스당 한 번만 처리합니다. NPC·문·상자의 실제 작동과 F 홀드 광역 줍기는 미구현입니다. 상호작용 후보의 매 프레임 거리·물리 검사 비용과 실제 화면·조작은 측정하지 않았습니다.

20일차의 임시 UI 정책은 체력·스킬·상호작용 HUD와 버튼 영역에서 시작한 클릭을 공격으로 전달하지 않습니다. 실제 텍스트 편집 또는 활성 `CombatInputFocus`가 있으면 이동·회피·일반 공격·스킬·상호작용 입력을 차단합니다. 여러 화면이 입력을 점유하면 마지막 화면이 비활성화될 때 해제합니다. 차단을 거친 마우스 홀드는 버튼을 놓기 전까지 공격에 사용하지 않으며, 일반 버튼이 선택된 것만으로는 키보드를 막지 않습니다. 게임 시간이나 적 행동은 정지하지 않습니다. 인벤토리·설정 화면과 일시정지 정책은 미구현입니다.

피해 계산은 문서 `1.11.3`의 단계별 버림을 첫 구현의 임시 기준으로 사용합니다.

- 일반 피해: `max(1, floor(최종 공격력 × 공격 배율 − 대상 방어력 × 0.5))`
- 치명타 피해: `floor(일반 피해 × 1.5)`
- 공격 배율 1인 레벨 1 검 비치명타는 슬라임에게 `floor((10 + 12) − 2 × 0.5) = 21` 피해를 주며 3회 적중으로 처치합니다.
- 같은 조건의 활 비치명타는 `floor((10 + 10) − 2 × 0.5) = 19` 피해를 줍니다.
- 같은 조건의 지팡이 비치명타는 `floor((10 + 8) − 2 × 0.5) = 17` 피해를 줍니다.

## 첫 전투 임시값

슬라임 행동의 세부 수치와 시험 배치 수는 기획에서 정해지지 않아 전투 흐름을 시험할 수 있도록 임시로 정했습니다. 제공된 `Assets/Phi/Data/PrototypeSettings.asset`에서 조정합니다.

| 항목 | 임시값 |
|---|---:|
| 이동속도 | 1.5 월드 단위/초 |
| 공격 시작 거리 | 0.9 월드 단위 |
| 공격 간격 | 1.2초 |
| 공격 예고 | 0.4초 |
| 돌진 거리·속도 | 0.8 월드 단위·초당 5 월드 단위 |
| 돌진 적중 거리 | 0.65 월드 단위 |
| 초기 슬라임 수 | 3마리 |

활은 발사 순간의 조준 방향을 유지하는 직선 비관통 투사체이며 최초 적 또는 장애물에서 종료합니다. 속도 초당 14월드 단위는 기획서 데이터 표의 시험 예시이고 `PrototypeSettings`에서 조정합니다. 플레이어 중심 발사, 0.1×0.1월드 단위 화살 도형과 충돌 반경 0.05, 적과 벽의 동률 시 벽 우선은 임시 정책입니다. 슬라임의 사각 충돌체는 현재 도형과 같은 크기를 사용합니다. 씬 맵 외곽 경계도 화살을 종료합니다. 낮은 FPS에서 이동 중인 적과 화살의 상대 운동으로 생기는 스침 판정은 미검증입니다.

지팡이는 +8 공격력, 0.90초 간격, 사거리 5.5, 반경 1.1, 최대 4대상을 사용하며 마나를 소비하지 않습니다. 마법탄 속도 초당 9월드 단위는 기획서 데이터 표의 시험 예시입니다. 적에 닿거나 사거리에 도달하면 폭발합니다. 내부 벽과 씬 외곽에 먼저 닿으면 폭발하지 않고 소멸하며, 폭발 중심에서 벽에 가려진 대상은 제외합니다. 이 벽 처리 방식은 임시 정책입니다.

폭발은 적의 중심이 반경 안에 있는 생존 대상을 중복 제거한 뒤 폭발 중심에 가까운 순서로 최대 4명에게 적용합니다. 거리 동률은 슬라임 생성 순서를 사용합니다. 적과 충돌했을 때 폭발 기준은 접촉면이 아닌 충돌 순간의 마법탄 중심입니다. 플레이어 중심에서 발사하는 청색 도형의 크기 0.1월드 단위, 충돌 반경 0.05, 원형 효과 지속시간 0.15초는 임시값입니다. 효과 링은 실제 판정 반경보다 약간 안쪽의 근사 표시입니다. 낮은 FPS에서 이동 중인 적과 마법탄의 상대 운동으로 생기는 스침 판정은 미검증입니다.

시험 공간은 기본 중심 `(0, 0)`, 가로 반폭 10·세로 반높이 6 월드 단위인 사각형이며 기본 테두리 두께는 0.12입니다. 크기와 두께는 조작감을 시험하기 위한 임시값입니다. 맵은 씬의 `Map > Map Floor > Boundary Top / Bottom / Left / Right`에 저장되며 실행 시 맵을 생성하지 않습니다. 바닥을 이동·크기 조절하면 자식 경계도 이동·비례 확대됩니다. 바닥과 경계는 회전하지 않고 축에 맞춥니다. 실제 배치된 바닥과 경계가 판정 기준이며 기존 `PrototypeSettings`의 `mapHalfWidth`, `mapHalfHeight`는 데이터 보존용으로 남기고 판정에 사용하지 않습니다.

플레이어와 슬라임의 도형 전체가 테두리 안에 머물도록 각각의 최대 반폭을 반영합니다. 카메라는 화면비와 맵 크기에 맞춰 직교 시야를 최대 6에서 줄이고 맵 안에서 플레이어를 추적합니다. 이 시야 기준도 임시값입니다. 조준 표시 길이는 경계에서 줄이고 체력 막대는 본체 안쪽에 표시합니다.

검은 `PhiObstacle` 레이어의 비트리거 Collider2D가 플레이어와 적의 중심선을 가리면 해당 적에게 피해를 주지 않습니다. 가려진 적은 최대 적중 수에 포함하지 않습니다. `PhiPlayer`와 `PhiEnemy` 레이어도 구분하며 첫 씬에는 내부 장애물을 추가하지 않았습니다. 플레이어와 적의 내부 장애물 이동 충돌은 구현되지 않았습니다. 위 임시값은 플레이와 성능 검증 후 조정이 필요합니다.

## 후속 결정 사항

장비 개별 인스턴스와 아이템 템플릿, 영구 저장 데이터와 출정 임시 상태를 분리하고 드롭·제작·상점·인벤토리를 공통 ID로 연결합니다. 세부 저장 구조는 해당 기능을 만들기 전에 확정해야 합니다. 적과 투사체가 많아지는 단계에서 풀링과 생성·해제 비용을 검토합니다.

전달문에 설명된 참고 화면의 강화 +11, 레전드 등급, 돌진 베기와 예시 수치는 확정 데이터가 아닙니다. 현재 초기 강화 계획은 +0~+5이고 등급은 일반·고급·희귀·영웅이며 첫 프로토타입은 일반 등급을 우선합니다. 참고 이미지 실물은 확인하지 못했습니다.
