# 18일차 회피와 스태미나 구현 계획

**목표:** Shift 회피와 스태미나를 기존 전투에 연결하고 무적·경계 및 장애물 충돌·공격과 스킬의 입력 구간을 시험합니다. 맵은 저장된 씬 하이어라키에서 읽으며 생성하거나 변경하지 않습니다.

---
## 기획 기준

[게임 기획서](https://docs.google.com/document/d/1Y8ZQw0Hr8II-M7drDmApz_opwwH_2sNFR54sO2Z4cPU/edit) 1.9.4·1.9.6·1.11.5·1.11.9와 6.2.4의 시험 기준입니다. 값은 최종 밸런스가 아닙니다.

- 이동 중 Shift를 누르면 현재 입력 중인 이동 방향으로 회피합니다. 이동 입력이 없으면 현재 마우스 조준의 반대 방향을 사용하며 조작감 확인 후 확정합니다.
- 기본 최대 스태미나는 100, 회피 비용은 25, 이동 시간은 0.25초, 쿨다운은 1.2초입니다.
- 회피 후 1초 대기한 뒤 초당 15를 재생하고 최대치를 넘지 않습니다. 화면의 스태미나는 정수로 표시합니다.
- 18일차 검증 범위는 무적·충돌·공격 취소 구간입니다. 이동 거리, 정확한 무적 구간과 행동 취소 규칙은 기획에서 확정하지 않았습니다.

---
## 조정 가능한 임시 정책

- 시험 회피 거리는 2.0 월드 단위로 두고 0.25초 동안 일정한 속도로 이동합니다. 별도의 거리·지속 시간·무적 시간 필드는 설정 에셋에서 변경할 수 있게 둡니다.
- 회피 시작부터 이동 종료까지 0.25초 전체를 임시 무적 구간으로 둡니다. 무적 표시를 제공하며 플레이어 피해의 공통 경로에서만 차단하고 적의 피해와 사망 로직은 바꾸지 않습니다.
- 회피 시작 시 비용과 쿨다운을 즉시 적용합니다. 스태미나 부족·대기시간·사망·텍스트 편집 중의 입력에는 비용과 대기시간을 적용하지 않습니다. Shift를 누른 순간에 한 번만 발동하고 키를 계속 눌러 자동 반복하지 않습니다.
- Shift를 누른 프레임에는 무적과 자원 소모만 즉시 적용하고 이동은 다음 프레임에 시작합니다. 직전 프레임의 경과 시간으로 새 회피가 조기 종료되지 않도록 기존 상태를 먼저 갱신한 뒤 새 입력을 처리합니다.
- 재생 대기의 기준은 문서의 '회피 후' 표현에서 시작 시점과 이동 종료 시점이 명확히 구분되지 않으므로 우선 **이동 종료 후 1초**로 둡니다. 같은 프레임의 경과 시간 중 대기 종료 이후 부분만 회복에 적용하고 시험과 문서에 이 선택을 드러냅니다.
- 씬 경계 내부에 플레이어 크기를 고려해 이동하고, 내부 `PhiObstacle`의 비트리거 충돌체에는 플레이어 반경으로 이동 경로를 연속 검사해 막힙니다. 장애물에 도달하면 이번 회피의 남은 시간 동안 그 자리에서 종료를 기다리며 벽을 통과하거나 반대편으로 순간 이동하지 않습니다. 벽에 막혀도 이미 사용한 자원은 반환하지 않습니다. 시작 위치가 장애물에 겹친 특수 상황은 제자리에서 차단합니다.
- 일반 이동은 기존 처리를 보존하며 회피 이동에만 위의 장애물 연속 검사를 적용합니다. 실제 맵 오브젝트의 변경·생성은 수행하지 않습니다.
- 플레이어 사각 크기의 BoxCast와 OverlapBox로 장애물 후보를 검사합니다. OverlapBox와 `Collider2D.Distance`가 실제 침투 없이 접촉 여유를 반환하므로 일시 활성화한 검사 도형으로 거리를 구하고 모서리 반경이 0인 박스·원형 장애물은 접촉 여유를 보정합니다. 접근 거리를 보정된 간격과 접촉 법선의 지지선까지로 제한하므로 원형 장애물에 비스듬히 접근할 때 실제 접촉 전 보수적으로 멈출 수 있습니다. 이외의 Collider 유형과 모서리 반경이 있는 박스는 침투 여부가 불명확하면 보수적으로 차단하며 접촉한 상태에서 반대 방향 이동도 막힐 수 있습니다. 검사 도형은 사용 후 즉시 비활성화하고 전투 종료 시 제거합니다.
- 회피 발동 프레임과 이동 중에는 새 일반 공격과 스킬 입력을 처리하지 않습니다. 이미 발생한 검 피해·발사된 투사체와 기존 무기·스킬 쿨다운은 취소하거나 초기화하지 않습니다. 회피가 끝나고 공격 홀드가 유지되면 기존 간격에 따라 공격을 재개합니다. 시전 선딜·후딜이 없는 현재 프로토타입에서의 임시 입력 우선순위이며 향후 애니메이션과 행동 취소 구간을 별도 설계합니다.
- 이동 키와 Shift가 같은 프레임이면 이동 키 방향을 우선하고, 대각선은 정규화합니다. 마우스 조준의 변경은 회피 방향을 바꾸지 않으며 이동 입력이 없을 때는 시전 프레임의 유효한 조준 방향 반대를 사용합니다.
- 회피와 마나·스태미나 재생은 게임 시간 기준이며 사망 중 진행하지 않습니다. 재시작은 체력과 마나뿐 아니라 스태미나·대기시간·회피 상태를 초기화합니다. 마을·장비에 따른 최대치 변화와 저장은 이번 범위에 포함하지 않습니다.

## 테스트 우선 작업 순서

1. 구현 전 편집 모드에서 상태 객체의 실패 테스트를 작성합니다. 기본 100·비용 25·부족과 정확한 비용, 1.2초 쿨다운 경계, 연속 재입력 실패, 0.25초 동작과 1초 재생 대기, 대기를 넘긴 프레임의 부분 회복, 초당 15와 최대치 제한을 결정적 경과 시간으로 검증합니다.
2. 플레이 모드에서 가상 Shift와 WASD로 이동 방향·대각선 정규화·입력 없음의 반대 조준·방향 고정·홀드 반복 방지·동시 Q/E/R 우선순위를 검증합니다. 텍스트 편집 중 차단 및 일반 UI 버튼 선택 시 허용도 확인합니다.
3. 기존 씬의 맵을 시험 인스턴스에서만 변형하여 맵 경계와 플레이어 반경을 검증합니다. 독립 시험 장애물로 회피 경로 중 비트리거 벽·트리거·고속 또는 긴 프레임·출발점 겹침을 확인하고 씬과 원본 설정 에셋은 변경하지 않습니다.
4. 슬라임 돌진과 피해 경로를 이용해 회피 전·무적 중·종료 후 피해 여부를 검증합니다. 일반 공격과 스킬의 회피 전·중·후 동작, 이미 발사된 투사체·독립 쿨다운 보존, 사망·재시작의 자원 초기화와 스태미나 표시를 확인합니다.
5. 이전 형식의 설정 **사본**에서 새 필드를 제거하고 재가져와 기본값과 기존 필드·원본 파일·GUID·씬 참조 보존을 확인합니다. 구현 전 실패를 확인한 뒤 최소 코드와 에셋 메타 파일을 추가합니다.
6. 별도 Unity 프로젝트 복사본에서 전체 편집·플레이 모드 회귀를 실행하고 실제 화면·실물 입력과 성능의 검증 여부를 분리해 기록합니다. 각 시험 결과와 임시값을 문서화한 뒤 18일차 작업을 커밋·푸시합니다.

## 현재 검증 결과

구현 전 편집 모드에서 기존 23개 테스트가 통과하고 새 회피 상태 테스트 4개가 실패했습니다. 구현 후 플레이 모드 회귀에서 벽 접촉 후 반대 방향 회피 실패를 확인했고, 실제 접촉과 Unity의 물리 쿼리 접촉 여유를 분리해 처리한 뒤 회피 전용 30개와 플레이 모드 전체 110개 테스트가 통과했습니다. 이전 설정 사본의 회피 기본값 검사를 포함한 편집 모드 전체 28개도 통과했습니다.

검증 복사본의 맵은 루트 `(3, -2)`·바닥 16×10과 다른 스프라이트이며 시작 설정은 `Staff`, 체력 137·공격력 13, 슬라임 6마리, Q 빈값·E/R 중복입니다. 개별 시험은 필요한 씬 인스턴스와 설정을 복제하며 원본 맵과 설정 에셋은 변경하지 않았습니다. 자동 시험은 좌우 Shift·대각선·조준 반대 방향, 긴 프레임, 스태미나·쿨다운, 슬라임 돌진 무적, 공격과 스킬 차단·기존 투사체 유지, 재시작, Box/Circle 접촉·실제 침투·트리거·접촉 후 탈출을 포함합니다. 전역 `Physics2D.defaultContactOffset` 0.01·0.02 조건도 시험했습니다. 다른 Collider의 접촉 후 탈출, 실제 입력·화면·수동 플레이와 성능은 미검증입니다.
