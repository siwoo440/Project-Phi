# 20일차 HUD와 전투 입력 포커스 계획

**목표:** HUD 클릭을 전투 공격으로 전달하지 않고, 전투 입력 포커스를 가진 UI와 실제 텍스트 편집 중 전투 입력을 차단합니다.

**기준:** 기획서 6.2.4의 20일차 완료 기준은 UI 클릭 중 공격 차단입니다. 본문 1.9의 UI 입력 포커스는 일반 공격과 스킬을 차단하고 HUD 클릭은 UI에서 처리합니다. 기존 HP·MP·ST·스킬 대기시간 및 상호작용 HUD와 무기 버튼을 유지합니다.

**임시 정책:** 별도 인벤토리·설정·채팅 화면은 아직 없으므로, 미래 UI가 활성 포커스 표시 구성 요소를 붙여 전투 입력을 점유하는 공통 경로를 제공합니다. 동시에 열린 포커스 화면은 모두 닫혀야 해제됩니다. 텍스트 편집 또는 해당 포커스 동안 이동·회피·일반 공격·스킬·상호작용 입력을 차단하되 게임 시간과 적 행동은 멈추지 않습니다. 단순 버튼 선택만으로 키보드 입력을 차단하지 않습니다. 차단 중 시작하거나 차단을 거친 마우스 홀드는 놓을 때까지 공격을 재개하지 않습니다. 비활성·파괴된 포커스 화면은 즉시 점유를 해제합니다.

**HUD:** 스킬과 상호작용 안내의 실제 UI 영역을 포인터 검사에 포함합니다. 체력 패널과 무기 버튼의 기존 처리는 보존합니다. 맵은 씬에 저장된 하이어라키를 읽으며 생성·변경하지 않습니다.

**검증:** 새 플레이 모드 시험에서 각 HUD 위 클릭·드래그 차단과 UI 밖 재클릭, 실제 입력 필드 포커스, 명시적 화면 포커스의 중첩·해제·파괴, 마우스 홀드 해제와 무기 버튼 입력을 확인합니다. 기존 설정은 복제하고 원본 맵과 에셋을 보존합니다. 구현 전 실패를 확인한 뒤 수정하고 편집·플레이 모드 전체 회귀를 실행합니다. 실물 입력과 화면, 성능의 미검증 여부를 별도 기록합니다.

## 수행 결과

- 구현 전 HUD 클릭·텍스트 편집·화면 포커스 시험 3개가 각각 예상한 미구현 동작으로 실패했습니다. 공격 홀드 중 화면을 열고 닫는 별도 시험도 기존 전투 코드에서 실패하는 것을 확인했습니다.
- 수정 후 Unity 복사본의 편집 모드 29개와 플레이 모드 전체 135개가 통과했습니다. 기존 시험의 HUD 입력 통과 기대는 기획과 충돌해 제거했으며, 새 시험은 실제 클릭과 드래그를 검증합니다.
- 전체 135개 통과 뒤 새 시험의 사용자 설정 격리와 포커스 해제 후 스킬·수집 확인을 보완하고, 해당 플레이 모드 시험 4개를 별도로 재실행해 모두 통과했습니다. 실물 입력·화면·수동 플레이 및 성능은 미검증입니다.
