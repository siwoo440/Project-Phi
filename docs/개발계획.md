# 개발 계획

핵심 흐름은 마을 준비 → 전투·탐험·채집 → 귀환·보상 정산 → 제작·판매·성장 → 재출정입니다. 각 단계는 실제 실행 가능한 상태를 유지하며 진행합니다.

---
## 단계별 목표

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 1 | 플레이어·검·슬라임 최소 전투 | 이동·조준·공격·피격·사망·재시작이 연결됨 |
| 2 | 무기 3종·공용 스킬 3개·회피·일반 적 5종·오우거 | 무기·스킬·적의 역할 차이를 플레이로 확인 |
| 3 | 던전 구역·목표·귀환·보상 | 한 번의 출정을 시작하고 정산까지 완료 |
| 4 | 임시·영구 성장·인벤토리·장비·저장 | 다음 출정과 재실행 시 유지·초기화가 정확함 |
| 5 | 채집·제작·골드·NPC 상점·납품 | 획득 → 제작 또는 판매 → 재투자 가능 |
| 6 | 수동 경제 이벤트 3종·로그·밸런스 | 이벤트 전후 활동 선택과 수입 비교 |
| 7 | 성능·사용성·통합 검증 | 밀집 전투와 반복 출정에서 주요 오류 해결 |

마을 1개, 전투 지역 1개, 던전 1개를 목표로 하되 작은 테스트 공간에서 먼저 검증합니다. 기획서의 60작업일은 참고 일정입니다. 현재 구현과 빠진 선행 작업을 반영해 MVP는 82일차까지, 조건부 후속 초안은 140일차까지 재구성했습니다. 일차는 상대 작업 순서이며 실제 소요 시간이나 확정 납기가 아닙니다.

2026-11-07 기준 1~25일차의 구현 기록이 있습니다. 실제 화면·키보드·마우스의 수동 검증과 성능 측정은 남아 있습니다. MVP 일정은 26~82일차로 **57개 상대 작업일**이고, 조건부 후속 초안은 83~140일차로 **58개 상대 작업일**입니다. 두 구간은 합계 115개 상대 작업일이며, 실제로 걸리는 날짜나 전체 게임의 최종 완료 시점은 미정입니다.

## 미산정 범위와 결정할 사항

- 확장 몬스터 120종과 개별 무기 모델 60종은 후보 목록입니다. 위 일정은 데이터 정리와 선정된 일부의 시험을 포함하며, 모든 후보의 완전 구현·애니메이션·밸런스 일수는 산정하지 않았습니다.
- 근접 무기 24개 모델 중 20개에는 이미지가 연결돼 있고, 유적 파수망치와 낫 모델 3개의 이미지는 기획서에 `예정`으로 표시돼 있습니다. 원거리·마법 모델의 개별 이미지 적용 가능 여부는 확인 작업으로 남깁니다. 현재 게임에는 기본 검·활·지팡이와 슬라임 점액 이미지만 적용돼 있습니다.
- 스킬 획득·해금·강화 상한, 드롭 확률·수량, 사망·포기 시 보상 보존율, 시작 지급 구성·골드, 방패와 양손 무기의 동시 장착 규칙 등은 기획서에서 미정입니다. 각 관련 작업 전에 정책을 정하고 시험값과 확정값을 구분합니다. 무기 희귀도는 기획서의 초기 가정에 따라 일반 등급부터 시험합니다.
- 유저 거래소·캐시·AI 자동 경제 조정은 MVP 범위가 아닙니다. 서버·결제 도입 여부와 정책 검토는 후속 게이트에서 결정합니다. 게임 내 현금 출금은 초기 기획의 미지원 범위입니다.
- 경제 데이터 집계·권장가의 일일 갱신과 주간 이벤트·주요 파라미터 갱신의 관계 및 허용 범위는 기획서의 가정 간 관계를 확인한 뒤 결정합니다. AI에 지갑·아이템 소유권 직접 변경 권한을 주지 않습니다.
- Windows 독립 실행 파일은 현재 작업 범위에서 생성하지 않습니다. 추후 빌드 시점과 전달 방식은 별도로 결정합니다.

## 첫 단계 완료 기준

1. 테스트 씬에서 WASD 이동과 대각선 정규화, 카메라 추적, 독립적인 마우스 조준을 확인합니다.
2. 좌클릭 1회와 홀드 공격의 간격, 전방 부채꼴 판정과 공격당 대상 중복 방지를 확인합니다.
3. 슬라임의 접근·공격·피격·사망과 플레이어의 피격·체력 표시·사망을 확인합니다.
4. UI를 클릭해도 공격하지 않고 재시작 시 전투 상태가 초기화되는지 확인합니다.
5. 레벨 1 플레이어의 검 비치명타가 슬라임에게 21 피해를 주고 3회 적중으로 처치되는지 확인합니다.

첫 전투가 동작한 뒤 간단한 밀집 시험을 시작합니다. 일반 전투 60 FPS를 목표로 50마리부터 100마리 이상까지 부하를 시험하며 기준 PC·해상도·이펙트 수와 통과 조건은 별도로 정합니다.
